# Grundlagsmonitor

A static prototype that tracks changes to Sweden's four constitutional laws and shows constitutional proposals pending a second vote after an intervening parliamentary election.

## Data model

- Ferenda / lagen.nu is the primary source for SFS, consolidated texts, amendment registers, and historical versions.
- The Swedish Parliament's open data (`data.riksdagen.se`) is the primary source for committee reports, parliamentary workflow, decisions, and vote summaries.
- Riksdagens paginated document-list API is also the discovery layer for pending cases: the updater searches for `vilande grundlagsförslag` and `grundlagsförslag`, then verifies candidate proposal text for `antar som vilande`.
- The Swedish Election Authority's election-day page is used for the next election date.
- `data/changes.json` is the only data file needed by the frontend. It is generated by `scripts/update_data.py`.

## Run locally

```bash
uv run --with certifi scripts/update_data.py
npm install
npm run dev
```

`npm run build` creates a fully static `dist/` directory suitable for GitHub Pages or statichost.eu.

## Nightly update

`.github/workflows/update-data.yml` runs the Python script with `uv` every night and commits only `data/changes.json` when the snapshot changes. The frontend makes no API requests in the browser.

## Important limitation

Ferenda's SFS register can show that an amendment entered consolidated legal text, but it does not expose a complete process model for the first vote, intervening election, or second vote. The pending queue therefore comes from the Parliament's document API and the curated cases from the source PDF. Riksdagens API has no single authoritative `pending` field: the updater infers a first dormant vote from the wording of an adopted proposal and does not treat the absence of a later decision as proof that a proposal fell. Older Ferenda search hits that mention dormant constitutional proposals but cannot be matched to a confirmed SFS amendment are shown as review signals.
